1. Context & Key Findings from Source

ClawRouter (@blockrun/clawrouter v0.12.199) is a payment proxy for BlockRun's unified LLM API. Its core value is intelligent model routing and x402 micropayment handling — not direct routing to OpenAI/Anthropic. Compression is applied before forwarding to BlockRun's API.

For the Phase 1 benchmark, we do not run ClawRouter as a full proxy. We call its compressContext() function directly via a thin Node.js shim, then make real API calls to OpenAI/Anthropic from the Python harness. This avoids the wallet/payment infrastructure entirely while faithfully using ClawRouter's exact compression code.

3. ClawRouter Compression Shim

The shim is a ~50-line Node.js ESM script written into the workdir by the Python harness during setup. It imports the compiled compressContext() from ClawRouter's dist/ and exposes it over HTTP.

// workdir/clawtypeor/cr_shim.mjs  (written by harness, not committed)
import { createServer } from "http";
import { compressContext } from "./dist/compression/index.js";

const PORT = parseInt(process.env.CR_SHIM_PORT ?? "8461");

// All 7 layers enabled explicitly — see Design Decision #2
const FULL_CONFIG = {
  deduplication: true,
  whitespace: true,
  dictionary: true,
  paths: true,
  jsonCompact: true,
  observation: true,
  dynamicCodebook: true,
};

createServer(async (req, res) => {
  if (req.method === "GET" && req.url === "/health") {
    res.writeHead(200).end("ok");
    return;
  }
  if (req.method !== "POST") { res.writeHead(405).end(); return; }
  let body = "";
  for await (const chunk of req) body += chunk;
  try {
    const { messages, config } = JSON.parse(body);
    const result = await compressContext(
      messages,
      { ...FULL_CONFIG, ...(config ?? {}) },   // caller can override per-layer
    );
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify(result));
  } catch (e) {
    res.writeHead(500, { "Content-Type": "application/json" });
    res.end(JSON.stringify({ error: String(e) }));
  }
}).listen(PORT, () => console.log(`CR shim listening on :${PORT}`));

The shim is spawned by the harness as a subprocess. It inherits the process env, so setting LEANCTX_SIDECAR_URL in the harness before spawning controls whether Layer 8 runs.

4. Patches — Two Files Modified by apply_patch()

apply_patch(cr_dir) makes string replacements in two files. Both patches are idempotent (safe to run twice). Both must succeed before npm run build is called.

Patch A — src/compression/index.ts (Layer 8 hook)

The anchor is the unique line const compressedChars = calculateTotalChars(result); which is the very first line after all 7 layers complete. Inserting Layer 8 before this line means compressedChars naturally reflects Layer 8 savings in the returned stats — no second patching needed.

--- src/compression/index.ts (original) +++ src/compression/index.ts (patched) // ... end of codebook header prepend block ... + // ── Layer 8: leanctx ML prose compression (opt-in) ────────────────────── + // Enabled only when LEANCTX_SIDECAR_URL is set in the environment. + // When unset, this block is a complete no-op — CR behaviour is unchanged. + const _leanctxUrl = process.env.LEANCTX_SIDECAR_URL; + if (_leanctxUrl) { + const _hasEligible = result.some( + (m: NormalizedMessage) => + ["system", "user", "assistant"].includes(m.role) && + typeof m.content === "string", + ); + if (_hasEligible) { + try { + const _resp = await fetch(`${_leanctxUrl}/compress`, { + method: "POST", + headers: { "Content-Type": "application/json" }, + body: JSON.stringify({ messages: result }), + signal: AbortSignal.timeout(5000), + }); + if (_resp.ok) { + const _body = (await _resp.json()) as { messages?: NormalizedMessage[] }; + if (Array.isArray(_body?.messages) && _body.messages.length === result.length) { + result = _body.messages; + } + } + } catch (_e) { + // sidecar timeout / unreachable — fall through with CR-only compression + } + } + } + // ── end Layer 8 ────────────────────────────────────────────────────────── + const compressedChars = calculateTotalChars(result); // ← anchor line (unchanged) const compressionRatio = originalChars > 0 ? compressedChars / originalChars : 1; return { messages: result, ... };

Patch B — tsup.config.ts (build entry point)

tsup builds a flat bundle from two entry points only. dist/compression/index.js does not exist in the default build, so the shim's import { compressContext } from "./dist/compression/index.js" would fail at runtime. Adding "src/compression/index.ts" as a third entry point causes tsup to compile it as a standalone module alongside the existing bundle.

--- tsup.config.ts (original) +++ tsup.config.ts (patched) export default defineConfig({ - entry: ["src/index.ts", "src/cli.ts"], + entry: ["src/index.ts", "src/cli.ts", "src/compression/index.ts"], format: ["esm"], dts: true, ...
📌 The anchor entry: ["src/index.ts", "src/cli.ts"], is unique in the file. The replacement is exact. After this patch, npm run build emits dist/compression/index.js as an ESM module alongside the existing dist/index.js bundle.

Python apply_patch() — combined implementation

def apply_patch(cr_dir: Path) -> None:
    _patch_compression_ts(cr_dir)
    _patch_tsup_config(cr_dir)

def _patch_compression_ts(cr_dir: Path) -> None:
    target = cr_dir / "src/compression/index.ts"
    src = target.read_text()
    ANCHOR = "  const compressedChars = calculateTotalChars(result);"
    if ANCHOR not in src:
        raise RuntimeError(
            f"Patch A anchor not found in {target}. Re-check --cr-commit."
        )
    if "LEANCTX_SIDECAR_URL" in src:
        return  # idempotent
    target.write_text(src.replace(ANCHOR, LAYER8_TS_BLOCK + "\n" + ANCHOR))
    print(f"[patch A] Layer 8 injected into {target.relative_to(cr_dir)}")

def _patch_tsup_config(cr_dir: Path) -> None:
    target = cr_dir / "tsup.config.ts"
    src = target.read_text()
    OLD = 'entry: ["src/index.ts", "src/cli.ts"],'
    NEW = 'entry: ["src/index.ts", "src/cli.ts", "src/compression/index.ts"],'
    if OLD not in src:
        if "src/compression/index.ts" in src:
            return  # idempotent
        raise RuntimeError(
            f"Patch B anchor not found in {target}. Re-check --cr-commit."
        )
    target.write_text(src.replace(OLD, NEW))
    print(f"[patch B] Compression entry added to {target.relative_to(cr_dir)}")
✓ Patch A anchor verified unique — calculateTotalChars(result) appears exactly once (line 177, confirmed against pinned commit). Patch B anchor verified unique — the entry: [...] line appears exactly once in tsup.config.ts.

9. Go / No-Go Gate

Phase 1 passes if BOTH conditions hold (on LongBench Stage 1)

  • Condition A — savings: (tokens_A − tokens_B) / tokens_A ≥ --savings-threshold (default 0.20). Must hold on at least one of: Agent S1, Agent S2, LongBench S1.
  • Condition B — quality: acc_B ≥ acc_A − --accuracy-drop (default 0.02). Measured on LongBench S1. An accuracy gain is also a pass.

Auto-retry: if A passes but B fails, the harness automatically reruns LongBench S1 with --lingua-ratio 0.65 before declaring no-go. Both results go into the report.

No-go outcome: write findings to phase1_report.md and stop. The Phase 2 shipping work does not start.

13. Design Decisions Log

Decision #1 — Use ClawRouter compression shim, not full proxy

ClawRouter is a BlockRun payment proxy, not a generic multi-provider router. Running it as a full proxy requires wallet/x402 payment infrastructure. Instead, we call compressContext() via a thin Node.js shim that exposes it over HTTP. The eval LLMs (OpenAI/Anthropic) are called directly from the Python harness. This is strictly equivalent for measuring compression quality while avoiding unrelated payment complexity.

Decision #2 — Use all 7 layers (full config), not DEFAULT_COMPRESSION_CONFIG ✓ confirmed

DEFAULT_COMPRESSION_CONFIG enables only dedup, whitespace, and JSON compaction. Dictionary encoding, path shortening, observation compression, and dynamic codebook are disabled by default. For the benchmark we enable all 7 layers. Rationale: we want to show leanctx adds value on top of ClawRouter's maximum structural compression — the strongest possible baseline for CR and the hardest case for leanctx. If leanctx passes at all 7 layers, it will easily pass at the 3-layer default. Note: the codebook/dictionary layers prepend a codebook header into the messages (already accounted for in the token count — this is correct because that header is what actually gets sent to the eval LLM).

Decision #3 — 50-turn agent_extended episode structure

5 episodes of ~10 turns each. Episodes vary file paths, error types, and tool names to stress-test both CR's structural layers (path shortening, dedup) and leanctx's prose compression. Structure:

  1. Episode 1 — grep & triage: long tool_result logs with repeated INFO heartbeat lines (tests CR observation compression + leanctx on prose analysis messages)
  2. Episode 2 — file reads: reading config/source files with prose comment blocks alongside code (tests verbatim code preservation + leanctx on the prose commentary)
  3. Episode 3 — error analysis: tracebacks + model reasoning prose back-and-forth (tests error verbatim + leanctx on assistant reasoning turns)
  4. Episode 4 — fix iteration: multiple proposed-fix rounds with verbose prose rationale (tests leanctx on repetitive framing language)
  5. Episode 5 — verification: test-runner output (verbose, repetitive) + summary (tests CR JSON compaction on structured test output + leanctx on the summary)

Decision #4 — Lingua ratio default 0.5, auto-retry at 0.65 if accuracy gate fails

0.5 is consistent with leanctx's published LongBench benchmarks. If the accuracy gate fails at 0.5, the harness automatically retries at 0.65 before declaring no-go. Both results are recorded. Ratio is exposed as --lingua-ratio for manual tuning.

Decision #5 — Real API calls, no mock LLM

The eval LLM receives the actual compressed messages and returns real answers. Token counts come from the API's usage.input_tokens field — the most accurate possible measurement (the LLM's own tokenizer). API keys are loaded from a local .env file following the BENCHMARK_EVAL_PROVIDER / BENCHMARK_EVAL_MODEL convention.

Decision #7 — apply_patch() must also patch tsup.config.ts to create dist/compression/index.js ✓ resolved

tsup is configured with only two entry points (src/index.ts, src/cli.ts), splitting: false, and noExternal: [/.*/] — producing a flat bundle. No dist/compression/index.js exists in the default build, and src/index.ts does not re-export compressContext. The shim's import { compressContext } from "./dist/compression/index.js" would therefore fail at runtime. Fix: apply_patch() patches tsup.config.ts with a one-line addition ("src/compression/index.ts" as a third entry) so the build emits dist/compression/index.js alongside the existing bundle. Anchor: entry: ["src/index.ts", "src/cli.ts"], (unique in file). This extends the patch scope from one file to two; both are idempotent and both must succeed before npm run build.

Decision #6 — Patch anchor is const compressedChars = calculateTotalChars(result); (verified unique) ✓ verified

Verified against pinned commit 89269507 by fetching the raw source. calculateTotalChars appears 3 times total: once as the function definition (line 26) and twice as calls both using messages as argument (lines 137, 176 — these compute originalChars). The target form calculateTotalChars(result) with result as argument appears exactly once at line 177, assigned to compressedChars.
