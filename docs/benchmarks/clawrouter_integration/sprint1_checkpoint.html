3. Fixture Implementation

_agent_extended() in leanctx/bench/workloads.py builds a 50-message continuous conversation organized into 5 thematic episodes of 10 turns each. Each episode follows a consistent pattern:

# Per-episode turn pattern (10 messages)
user:       task description
assistant:  [text block + tool_use block]      ← triggers test 2
user:       [tool_result block]                ← triggers test 3 (linked IDs)
assistant:  long prose analysis (string)       ← triggers test 4 (> 400 chars)
user:       follow-up question
assistant:  [text block + tool_use block]      ← 2nd tool call per episode
user:       [tool_result block with code]      ← triggers test 5 (fenced blocks)
assistant:  analysis string
user:       clarifying question
assistant:  response string

Tool ID convention

IDs follow tu_e{episode}_{call} — e.g. tu_e1_01, tu_e3_02. This makes them human-readable and unique within the fixture. 10 tool_use / tool_result pairs total.

6. Open Issues & Questions

  • #1 open Python environment — no virtualenv for the project
    The project's .python-version pins 3.12.10 via pyenv, but the pyenv version has no packages installed. Tests were run on Homebrew Python 3.12.9 using --break-system-packages to install dev dependencies. This is fragile: the install mutates the system Python and will conflict with other projects on the machine.
    Impact: dev environment reproducibility; CI matrix may diverge from local.
    Recommended action: create a venv or uv environment at the project root, install pip install -e ".[dev]" into it, and update CLAUDE.md to document the setup command. Unblocks clean CI runs without --break-system-packages.
  • #2 open tests/bench/test_workloads.py created from scratch — no prior file to extend
    The implementation plan says "extend tests/bench/test_workloads.py" but the file did not exist before Sprint 1. It was created fresh. This is not a problem for Sprint 1 but signals that the test plan's description of file states may not perfectly reflect the repository at the time of Sprint 1 execution.
    Impact: none for Sprint 1. Future sprints should verify file-existence assumptions before calling "extend."
    No action needed — file now exists as specified for Sprints 2+.
  • #3 open tiktoken must be present for the token-count test to use accurate BPE counting
    test_agent_extended_total_tokens_above_threshold calls count_tokens() which falls back to a 4-chars-per-token estimate when tiktoken is not installed. With tiktoken: 10,769 tokens (passes comfortably). With the fallback: 38,246 chars ÷ 4 = 9,561 tokens (also passes, but with less margin). The test passes in both cases given the current fixture size, but the two paths give different absolute numbers.
    Impact: test is robust under both modes. Documented for completeness.
    No code change required. If CI runs without tiktoken, the test still passes.
  • #4 open agent_extended workload is not yet reachable via the leanctx bench run CLI
    The workload is registered in _WORKLOADS and accessible via load_workload("agent_extended"), but no scenario entry in leanctx/bench/scenarios.py references it. Running leanctx bench run agent-extended from the CLI would therefore fail with an unknown scenario error. This is expected — the CLI scenario will be wired in when the Phase 1 harness script is complete (Sprints 2–7).
    Impact: the workload cannot be benchmarked via the existing CLI. Sprint 7 addresses this through the harness script's run_leg().
    Deferred to Sprint 7 / scripts/bench_clawtypeor_phase1.py.
  • #5 open pytest markers warning silenced by adding markers to pyproject.toml — confirm CI uses the same config
    Before the pyproject.toml patch, the test run emitted 7 warnings: "PytestUnknownMarkWarning: Unknown pytest.mark.unit". The warnings are now gone (markers registered). However, CI workflows are not yet defined for this project (no .github/workflows/ directory), so the marker filtering (pytest -m unit) has not been validated in a CI context.
    Impact: low — the markers work locally. CI setup is defined in implementation_test_plan.html §CI but not yet created.
    Create .github/workflows/bench_phase1.yml as specified in the test plan (deferred to after Sprint 4 when the unit suite is fully green).
